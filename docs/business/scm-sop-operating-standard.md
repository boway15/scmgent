## 0. 目的

1. 运营与供应链只使用**一套共识需求**驱动补货与下单。
2. 需求与供应的冲突在**计划阶段**暴露并裁决，而不是在跟单、到货阶段被动消化。
3. 每个环节有唯一的最终负责人（A）、明确时限和升级路径。
4. 每个人工决策可追溯，可复盘“人工修正是否让结果更好”。

## 1. 术语

| 术语 | 含义 |
|------|------|
| S&OP | 销售与运营计划，月度的需求与供应平衡与决策 |
| S&OE | 销售与运营执行，周度的建议处理、下单、跟单与异常处理 |
| S&OP 负责人 | 不单设岗位，由供应计划 / PMC 负责人兼任；负责主持月度 S&OP、对供应承诺签字、处理 L2 例外、KPI 复盘 |
| 共识需求 | 经月度评审的需求版本：需求数字由运营负责人签字，供应承诺由 S&OP 负责人签字；系统中为已发布销售预测 + 已采纳的需求计划 |
| 补货建议 | 每周一系统生成的建议行，分自动队列（门禁通过）与手工队列（需人工判断） |
| 时界 | 按交期把未来划为冻结 / 半冻结 / 自由三段，越近越难改，见 §6 |
| 例外 | 系统预警、数据问题工单、门禁未通过的建议、跟单异常 |
| 原因码 | 人工忽略 / 改量 / 推翻预测时必须选择的标准原因，见 §7 |
| FVA | 预测附加值：人工修正后的误差 vs 系统基线误差，衡量修正是否有效 |

## 2. 运作原则

1. **一个数**：运营备货预期、补货建议、PMC 下单都取自当月共识需求，不允许各自另起口径。
2. **时界纪律**：冻结区内的变更走审批；半冻结区内的变更须供应计划确认；自由区内的变更由需求计划自行决定。
3. **例外管理**：门禁通过、无预警的 SKU 由系统自动推进；人只处理例外。
4. **留痕**：忽略建议、改量、推翻预测都必须填写原因码；未填写的视为流程未完成。
5. **单一 A**：同一事项只有一个最终负责人。运营负责人与 S&OP 负责人意见不一致时，在月度决策会（紧急时临时会议）当面对齐：需求侧问题由运营负责人拍板，供应侧问题由 S&OP 负责人拍板；两人仍无法达成一致的，上报双方共同上级。

## 3. 组织与角色

### 3.1 角色定义

| 角色 | 职责摘要 | 主要系统页面 |
|------|----------|--------------|
| 运营 / 销售 | 提供促销、新品、下架、渠道变化等需求情报；负责清仓动作 | 销量分析、销售预测 |
| 需求计划员 | 统计基线、需求修正、预测与需求计划发布；数据质量第一责任人（销量侧） | 销售预测版本、需求计划 |
| 供应计划 / PMC | 补货建议处理、PMC 计划确认下发、安全库存策略执行。**PMC 负责人兼任 S&OP 负责人**：主持月度 S&OP、对供应承诺与缺口方案签字、处理 L2 例外、审批超阈值下单、KPI 复盘 | 补货建议、规划页（时间轴）、PMC 计划、安全库存、经营看板 |
| 采购跟单 | 供应商交期确认、ETA 与里程碑维护、跟单异常处理 | 采购跟单 |
| 库存 / 仓储 | 到货登记、库存快照核对、调拨执行；数据质量第一责任人（库存侧） | 库存总览、数据问题队列、到货登记 |
| 运营负责人 | 对共识需求数字签字；超储与呆滞处置决策（清仓、停售）；运营侧争议的最终裁决 | 销量分析、需求计划、库存总览 |
| 系统 / 数据管理员 | 定时任务、飞书同步、快照发布异常的技术处理 | 任务运行记录 |

### 3.2 RACI

R = 执行，A = 最终负责（签字），C = 征询，I = 知会。“供应计划/PMC”列中的 A 由 PMC 负责人（即 S&OP 负责人）承担，R 由 PMC 计划员承担。

| 事项 | 运营/销售 | 运营负责人 | 需求计划 | 供应计划/PMC | 采购跟单 | 库存/仓储 |
|------|-----------|------------|----------|--------------|----------|-----------|
| 销量与库存数据质量 | C | I | R | A | I | R |
| 统计预测基线 | I | I | A/R | I | – | – |
| 需求修正（促销、新品、断货还原） | R | C | A | C | – | – |
| 共识需求签字（需求数字） | C | A | R | C | – | – |
| 供应承诺与缺口方案签字 | I | C | C | A/R | C | C |
| 安全库存与服务水平策略 | C | C | C | A/R | – | C |
| 补货建议采纳 / 忽略 / 改量 | I | – | C | A/R | – | C |
| PMC 计划确认下发（超阈值由 PMC 负责人审批） | – | – | I | A/R | C | – |
| 供应商交期与 ETA 维护 | – | – | I | C | A/R | I |
| 到货登记 | – | – | – | I | R | A |
| 超储与呆滞处置 | R | A | C | C | – | R |
| 例外升级与裁决 | C | A（需求侧） | C | A/R（供应侧） | R | R |
| KPI 复盘 | C | C | R | A/R | R | R |

## 5. SOP 细则

每条 SOP 按“目的 / 负责 / 触发 / 步骤 / 输出 / 时限 / 升级 / 系统落点”描述。“系统支持”一栏：✅ 已支持；⚠️ 线下执行，系统待建设（见 §10）。

### SOP-01 数据日检

- **目的**：保证当天所有计划计算基于正确的库存与销量。
- **负责**：A = S&OP 负责人；R = 库存/仓储（库存侧）、需求计划（销量侧）、系统管理员（技术处理）。
- **触发**：每个工作日 09:30 前；或 07:40 当日快照未发布。
- **步骤**：
  1. 确认当日库存周转快照已发布；未发布时通知系统管理员查看同步错误。
  2. 系统管理员 2 小时内修复并重跑，或经库存/仓储确认后沿用上一日快照，并在群内说明。
  3. 查看数据问题队列新增工单（缺上架时间、无法分仓、占比和偏差），按工单类型分派。
  4. 抽查前一日销量是否完整入库。
- **输出**：快照发布状态确认；工单分派记录。
- **时限** 〔建议值〕：快照问题 2 小时内处理；数据问题工单——影响时间轴或预警的 24 小时内关闭，其他 72 小时内关闭。
- **升级**：快照连续 2 天未发布 → L2；影响 A 类 SKU 的数据问题超 24 小时未关闭 → L2。
- **系统落点**：`inventory_data_issues`（状态 `open` / `in_progress` / `resolved` / `dismissed`）、任务运行记录。
- **系统支持**：✅ 快照校验与工单队列；⚠️ 工单责任人与时限字段。

### SOP-02 月度需求评审与共识发布

- **目的**：形成当月唯一的共识需求。
- **负责**：A = 需求计划（发布）/ 运营负责人（签字）；R = 需求计划；C = 运营/销售、供应计划、S&OP 负责人。
- **触发**：每月第 1 周，上月销量关账后。
- **步骤**：
  1. 生成统计基线预测；运营/销售在第 1 周内提交促销、新品、下架、渠道变化情报。
  2. 需求计划完成修正，处理全部评审项（接受或忽略，不允许遗留）。
  3. 与上一版相比，单 SKU 变化超过 **30%**〔建议值〕的必须填写修正原因码（§7）。
  4. 冻结区内的修改不得直接改动，需走 §6 的审批。
  5. 发布销售预测版本；试点项目组同时发布并采纳需求计划。
  6. 在月度决策会上由运营负责人对需求数字签字，S&OP 负责人对供应承诺签字。
- **输出**：已发布预测版本、已采纳需求计划、变化说明、签字记录。
- **时限**：第 2 周周五前发布；第 4 周决策会前签字。
- **升级**：运营与需求计划对数字有分歧 → 预备会讨论，决策会上由运营负责人裁决。
- **系统落点**：销售预测版本（`draft → published`）、需求计划（`draft → pilot_published`，采纳写 `planning_demand_adoptions`）。
- **系统支持**：✅ 版本评审、发布、冻结期；⚠️ 变化原因码、签字人与签字时间。

### SOP-03 周度补货建议处理

- **目的**：把共识需求转成可执行的补货量，并对人工判断留痕。
- **负责**：A/R = 供应计划/PMC；C = 需求计划、库存/仓储。
- **触发**：每周一 09:00 系统生成建议后。
- **步骤**：
  1. 自动队列（门禁通过）：核对后批量采纳；有疑问的转手工处理。
  2. 手工队列：查看规划页时间轴（确定缺货日、破安全日、在途与在产批次）后决定采纳、改量或忽略。
  3. 改量或忽略必须填写原因码（§7）。
  4. 采纳后按同商家、同目标仓合并为 PMC 草稿。
- **输出**：采纳 / 忽略 / 改量记录；PMC 草稿。
- **时限** 〔建议值〕：自动队列 24 小时内处理；手工队列 48 小时内处理。
- **升级**：同一 SKU 连续 3 周被忽略 → L2；因供应商产能不足而忽略 A 类 SKU → L3。
- **系统落点**：补货建议（`/reorder/suggestions`，队列 `auto` / `manual`）、规划页、PMC 草稿。
- **系统支持**：✅ 队列与采纳；⚠️ 强制原因码、连续忽略统计。

### SOP-04 PMC 计划确认与下发

- **目的**：把补货量下达给供应商并锁定交期。
- **负责**：A = PMC 负责人；R = PMC 计划员；C = 采购跟单。
- **触发**：PMC 草稿生成后。
- **步骤**：
  1. 核对数量、MOQ、交期、目标仓；必要时导出 CSV / XLSX 发给供应商预确认。
  2. 下单后预计覆盖天数超过**目标覆盖天数 × 1.5**〔建议值〕，或改量超过系统建议量 **±30%**〔建议值〕的，确认前须 PMC 负责人审批；PMC 负责人本人经办的，须知会运营负责人并在周五 S&OE 周会上说明。
  3. 确认计划（`draft → confirmed`），系统自动为每个计划行生成采购跟单。
  4. 采购跟单通知供应商并获取交期回复。
- **输出**：已确认 PMC 计划；采购跟单台账。
- **时限** 〔建议值〕：草稿 T+1 个工作日内确认；供应商 T+2 个工作日内回复交期。
- **升级**：供应商交期晚于需求日期且无法调整 → L2；影响 A 类 SKU → L3。
- **系统落点**：PMC 计划（`draft → confirmed → in_progress → completed`）、`purchase_drafts`（只能由计划确认生成）。
- **系统支持**：✅ 状态流转与自动生成跟单；⚠️ 超覆盖 / 超改量审批。

### SOP-05 跟单与 ETA 维护

- **目的**：让时间轴上的供给批次和真实进度一致。
- **负责**：A/R = 采购跟单；C = 供应计划/PMC。
- **触发**：跟单生成后持续执行；T-30 / T-14 / T-7 系统提醒。
- **步骤**：
  1. 按里程碑推进跟单状态：`confirmed → in_production → ready_to_ship → in_transit → partial_received / received`。
  2. 每次状态变化同步更新 ETA 与里程碑日期。
  3. ETA 推迟超过 **7 天**〔建议值〕：当天更新，并通知供应计划重新查看该 SKU 时间轴。
  4. 出现异常（质量、延期、短装）置为 `exception`，写明原因与恢复方案。
- **输出**：准确的跟单状态与 ETA。
- **时限** 〔建议值〕：状态变化当天更新；异常 24 小时内给恢复方案。
- **升级**：异常 48 小时无方案 → L2；导致 7 天内确定缺货 → 按 SOP-07 L2 处理。
- **系统落点**：采购跟单（`PATCH /purchase-drafts/:id`）、三池供给批次同步。
- **系统支持**：✅ 状态、ETA、提醒（跟单仍为 `draft` 时推送）；⚠️ ETA 大幅推迟自动通知。

### SOP-06 到货登记

- **目的**：到货即入账，防止重复或漏记。
- **负责**：A = 库存/仓储；R = 采购跟单（登记）、库存/仓储（核对）。
- **触发**：货物上架。
- **步骤**：
  1. 按跟单登记实收数量与收货日期；每次登记使用唯一的收货单号作为幂等键。
  2. 部分到货登记后跟单变为 `partial_received`，差异数量说明原因（短装、破损、分批）。
  3. 次日核对库存快照是否体现该到货；不一致时开数据问题工单。
- **输出**：收货记录、库存记录、计划完成进度。
- **时限**：上架当天登记。
- **升级**：短装或破损超过 **5%**〔建议值〕→ L2（索赔与补货决策）。
- **系统落点**：`POST /purchase-drafts/:id/receive`（重复幂等键直接返回原记录，不重复入账）。
- **系统支持**：✅。

### SOP-07 例外分级与升级

- **目的**：让例外在合适的层级、合适的时间被处理。
- **负责**：A = S&OP 负责人；R = 各级处理人。

| 级别 | 触发条件（示例） | 处理人 | 时限〔建议值〕 | 去向 |
|------|------------------|--------|----------------|------|
| L1 | 低于补货点、低于安全库存、覆盖天数不足总交期 | PMC 计划员 | 本周内 | 周一建议处理 |
| L2 | 7 天内确定缺货；新下单已来不及覆盖；跟单异常 48 小时无方案；快照连续 2 天未发布 | PMC 负责人（S&OP 负责人） | 48 小时内给出调拨 / 加急 / 空运 / 限售方案 | 周五 S&OE 周会 |
| L3 | A 类 SKU 缺货；A / B 类 SKU 超储超 180 天；需要改动冻结区需求；运营与供应链无法达成一致 | 运营负责人 + PMC 负责人共同决策（需求侧由运营负责人拍板，供应侧由 PMC 负责人拍板；仍不一致上报共同上级） | 当月决策会（紧急时临时会议） | 月度决策会 |

- **步骤**：发现 → 按上表定级 → 指派处理人 → 在时限内给出方案 → 执行 → 关闭并写结论。
- **规则**：超时未处理自动升一级；L2、L3 的结论写入会议纪要。
- **系统落点**：预警（`stockout`、`below_rop`、`below_safety`、`stockout_horizon`、`coverage_short`、`overstock`、`uncoverable_by_new_po`）、数据问题工单、跟单异常。
- **系统支持**：✅ 预警检测与飞书推送；⚠️ 定级、责任人、时限与自动升级。

### SOP-08 安全库存与服务水平策略评审（季度）

- **目的**：安全库存由策略决定，而不是沿用默认值。
- **负责**：A = PMC 负责人（S&OP 负责人）；R = PMC 计划员；C = 运营负责人、需求计划、库存/仓储。
- **触发**：每季度首月；或新品转常规、交期大幅变化时。
- **步骤**：
  1. 按 ABC（销量或销售额贡献）× XYZ（需求波动）给 SKU 分层；分层结果与运营负责人确认。
  2. 按分层确定方法与服务水平，参考：

     | 分层 | 方法 | 服务水平 / 天数〔建议值〕 |
     |------|------|---------------------------|
     | AX / AY | Z 值法（`z_demand`） | 97.5% |
     | AZ、BX / BY | Z 值法 | 95% |
     | BZ、C 类 | 覆盖天数（`coverage_days`） | 7–14 天 |

  3. 在安全库存页查看系统建议值与现配置的差异，逐分层评审后采纳。
  4. 特殊 SKU 可设为手动配置，须写明原因与复核日期。
- **输出**：更新后的 `safety_stock_config`；策略变更记录。
- **规则**：
  - 规划计算按配置生效：手动配置且件数大于 0 用手动件数；否则按配置的方法计算（默认覆盖天数 14 天）。
  - 周度补货任务不会覆盖手动配置。
- **系统落点**：安全库存页、`/safety-stock/suggestions`、`/safety-stock/:skuId`。
- **系统支持**：✅ 建议与采纳；⚠️ ABC/XYZ 自动分层。

### SOP-09 超储与呆滞处置（月度）

- **目的**：控制库存水位与仓容占用，及时处理慢动销库存。
- **负责**：A = 运营负责人；R = 运营/销售（清仓）、库存/仓储（调拨）；C = S&OP 负责人、需求计划。
- **触发**：月度数据准备时。
- **步骤**：
  1. 导出覆盖天数超过超储阈值（默认 180 天）和灰灯（滞销）SKU 清单，按超储件数（可参考货值）排序。
  2. 按调拨 → 促销清仓 → 停补 → 退货或销毁的顺序制定方案；清仓节奏与定价由运营决定。
  3. 停补的 SKU 更新生命周期或商品状态，使其退出补货建议。
  4. A / B 类 SKU 的处置方案，以及涉及退货或销毁的方案，提交决策会。
- **输出**：处置方案与负责人；停补清单。
- **时限**：当月决策会前出方案。
- **系统落点**：库存总览、预警 `overstock`、SKU 生命周期 / 商品状态。
- **系统支持**：✅ 超储识别与停补排除；⚠️ 超储清单按件数 / 货值排序的报表。

### SOP-10 月度 S&OP 会议

- **目的**：在运营需求与供应能力之间做出平衡决策。
- **负责**：A = S&OP 负责人（会议主持、供应承诺）/ 运营负责人（需求数字）；R = 需求计划（需求部分）、供应计划（供应部分）、库存/仓储（库存部分）。
- **预备会（第 3 周，60 分钟）**：
  - 参会：需求计划、供应计划/PMC、采购跟单、库存/仓储、运营代表。
  - 目标：把能在计划层解决的冲突解决掉，剩下的形成待决策事项与备选方案。
- **决策会（第 3–4 周，60 分钟）**：
  - 主持：S&OP 负责人（PMC 负责人）。
  - 参会：运营负责人、需求计划、PMC 计划员、采购跟单负责人（涉及供应商交期时）。
  - 议程：
    1. 上月 KPI 与上次决策执行情况（10 分钟）
    2. 需求变化与风险（10 分钟）
    3. 供应缺口与方案（15 分钟）
    4. 库存水位走势与目标（覆盖天数、超储件数）（10 分钟）
    5. 待决策事项逐项拍板（15 分钟）
- **会议包内容**（预备会前 1 个工作日发出）：
  1. 需求：本版 vs 上版变化最大的 SKU（件数）、变化原因码分布。
  2. 供应：未来 90 天确定缺货 SKU、新下单来不及覆盖的 SKU、供应商延期清单。
  3. 库存：未来 3 个月各仓覆盖天数走势、超储与呆滞件数（可附货值参考）。
  4. 流程：SOP 时限达成率、建议采纳率与忽略原因分布。
  5. 待决策事项：每项含背景、备选方案、各方案的影响与建议。
- **决策纪要模板**：

  | 编号 | 事项 | 决策 | 负责人 | 截止日期 | 状态 |
  |------|------|------|--------|----------|------|
  | 2026-10-01 | 例：SKU-XXX 空运补货 500 件 | 批准，优先发美西仓 | 供应计划 | 2026-10-10 | 进行中 |

- **系统支持**：⚠️ 会议包需人工汇总，待系统自动生成（§10 P1）。

## 6. 时界规则

| 区段 | 范围 | 允许的变更 | 审批 |
|------|------|------------|------|
| 冻结区 | 今天至生产周期结束（系统：前 `ceil(交期 / 30)` 个月不可编辑） | 仅加急、取消、替代料 | L3：运营负责人与 S&OP 负责人（PMC 负责人）共同批准，并记录原因码 |
| 半冻结区 | 生产周期结束至总交期 | 需求变动 ±20%〔建议值〕以内 | 供应计划确认；超过 ±20% 走 L2 |
| 自由区 | 总交期以外 | 任意调整 | 需求计划自行决定，月度发布 |

## 7. 标准原因码

忽略补货建议、改量、推翻预测或需求变化超过阈值时，必须选择其一。选择“其他”时须补充文字说明。

| 代码 | 含义 | 适用场景 |
|------|------|----------|
| D01 | 促销 / 活动 | 需求修正 |
| D02 | 新品 / 上新节奏 | 需求修正 |
| D03 | 下架 / 清仓 / 停售 | 需求修正、忽略建议 |
| D04 | 断货导致历史销量偏低（已还原） | 需求修正 |
| D05 | 预测明显偏高 / 偏低 | 需求修正、改量 |
| S01 | 供应商产能不足 | 改量、忽略建议 |
| S02 | MOQ / 整柜凑单 | 改量 |
| S03 | 交期不可满足，已改用其他方案 | 忽略建议 |
| S04 | 在途 / 在产数据未及时更新 | 忽略建议（须同时开数据问题工单） |
| O01 | 运营策略调整（渠道、定价、推广节奏） | 需求修正、改量、忽略建议 |
| I01 | 仓容不足 | 改量 |
| O99 | 其他（必须填写说明） | 任意 |

## 8. KPI 定义

| 维度 | 指标 | 口径 | 负责人 | 频率 |
|------|------|------|--------|------|
| 需求 | WMAPE | 最近已结算月，按实际量加权：Σ\|预测−实际\| ÷ Σ实际 | 需求计划 | 月 |
| 需求 | Bias | Σ(预测−实际) ÷ Σ实际；正值为偏高 | 需求计划 | 月 |
| 需求 | FVA | 系统基线 WMAPE − 人工修正后 WMAPE；为正说明修正有效 | 需求计划 | 月 |
| 供应 | 供应商准交率 | 实际到货日 ≤ 确认交期 + 容差 的跟单行数 ÷ 应到行数 | 采购跟单 | 月 |
| 供应 | PMC 确认时效 | 草稿到确认在 T+1 内的计划数 ÷ 计划总数 | 供应计划/PMC | 周 |
| 库存 | 有货率 | 可售 > 0 的 SKU × 仓 × 日 ÷ 总 SKU × 仓 × 日（排除停补 SKU） | S&OP 负责人 | 周 / 月 |
| 库存 | 周转天数 | 平均库存 ÷ 日均出库 | 库存/仓储 | 月 |
| 库存 | 超储 / 呆滞件数 | 覆盖天数 > 超储阈值的库存件数（可附货值 = 件数 × 单位成本作排序参考） | 库存/仓储 | 月 |
| 流程 | 建议采纳率 | 采纳行 ÷ 生成行（分自动 / 手工队列） | 供应计划/PMC | 周 |
| 流程 | SOP 时限达成率 | 各 SOP 按时完成的事项 ÷ 应完成事项 | S&OP 负责人 | 月 |

试点前 2 个月只取基线，不设考核目标；第 3 个月起由决策会确定目标值。
