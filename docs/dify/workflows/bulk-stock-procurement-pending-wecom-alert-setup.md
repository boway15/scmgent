# [家具/创新]_大件备货·待供应商确认超1天

从飞书多维表格 **大件备货申请** 拉取「待供应商确认」且**恰好超 1 天（前天当天）**的记录，由**采购跟进**催办，推送飞书群机器人。

> 与 `bulk-stock-wecom-alert.yml`（超 2 天）**同一状态、按日期互斥**，避免同一条出现在两条提醒里。

## 业务规则

| 项目 | 说明 |
|------|------|
| 数据源 | 飞书多维表格 `大件备货申请` |
| 服务端筛选 | 仅 `订单确认状态` = **待供应商确认** |
| 跟进人 | 采购 |
| 本地筛选 | **前天当天**。例：今天 `7/17` → 只统计 **`7/15`**；`7/14` 及之前归超 2 天提醒 |
| 推送格式 | 橙色卡片 **待供应商确认 · 超1天**；正文含「采购跟进」 |
| 查看明细 | [超1日视图](https://chinabestwo.feishu.cn/base/HPJzbHdPea7elSs92T8c31BTnxe?table=tbl7H8F6rc2xeFGf&view=vewZxNTnEj) |
| 定时 | 工作日 **09:10** |

### 与超 2 天提醒对比

| 对比项 | 超 2 天（`bulk-stock-wecom-alert.yml`） | 本工作流（超 1 天） |
|--------|----------------------------------------|---------------------|
| 订单确认状态 | 待供应商确认 | 待供应商确认 |
| 跟进人 | 采购 | 采购 |
| 日期窗口 | 大前天及之前（今天 7/17 → **7/14 及之前**） | 前天当天（今天 7/17 → **仅 7/15**） |
| 卡片 | 红色「待供应商确认 · 超2天」 | 橙色「待供应商确认 · 超1天」 |
| 查看明细 | `view=vewLM617rt` | `view=vewZxNTnEj` |
| 定时 | 工作日 09:00 | 工作日 09:10 |

## 节点链路

```
定时触发器
  → 解析超时阈值（超1天独占窗口）
  → 获取飞书 Token
  → 构建查表条件（待供应商确认 + 推送时间升序）
  → 查询飞书多维表格 (HTTP search)
  → 筛选超时待确认（只留前天当天）
  → 是否有待推送
      ├─ 是 → 按供应商生成推送内容 → 推送飞书 → 推送完成
      └─ 否 → 无待推送
```

## 导入步骤

1. Dify 控制台 → **工作室** → **导入 DSL** → 选择 `bulk-stock-procurement-pending-wecom-alert.yml`
2. 配置环境变量：`FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_APP_TOKEN`、`FEISHU_TABLE_ID`、`FEISHU_BOT_WEBHOOK_URL`
3. 覆盖导入后删除旧的 `WECOM_HOOK_KEY`，**保存并重新发布**
4. 定时默认工作日 09:10，与超 2 天 09:00 错开

## skipped_json

| 键 | 含义 |
|----|------|
| `status` | 不是「待供应商确认」 |
| `time_parse_fail` | 推送时间无法解析 |
| `time_too_recent` | 今天或昨天，未到超 1 天 |
| `time_too_old` | 已达超 2 天，归另一条提醒 |
| `sku` | SKU 为空 |
