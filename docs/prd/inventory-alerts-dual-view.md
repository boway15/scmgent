# 库存风险看板：按断货窗口分动作 PRD

> 版本：2026-09-30 ｜ 实现栈：React（`apps/web`）+ Hono + Postgres ｜ **不**走妙搭 ZIP。  
> 关联：`docs/business/scm-demand-supply-inventory-logic.md` §3.3 ⑥、`apps/web/server/lib/replenishment-coverage.ts`、`inventory-timeline.ts`。

入口是规划驾驶舱里的 **库存风险** 卡片区，形态对齐现有「风险与履约」：每个场景一块概览数字，点进去才是明细。明细上按场景给出该角色的动作。同一条只进最紧急的一档。

---

## 1. 需求分析

### 背景

成品范围待处理约 6.6 万行（SKU × 仓 × 类型）。现有类型（缺货、7/15/30 天、覆盖不足、低于 ROP、积压）和业务动作对不齐。业务按断货窗口分成四类动作：

| 档 | 距确定断货日 | 动作 | 负责人 |
|----|----------------|------|--------|
| 已确定断货 | 断货日 ≤ 今天，或发货、下单都赶不上 | **调价控销**，少卖、保利润 | 运营 |
| 发货 | ≤ 45 天：紧急发货；≤ 60 天：发货 | 把已有货（本地已完工 / 在产可发）发出海运 | 发运 |
| 下单 | ≤ 90 天、≤ 120 天 | 向工厂下新单 | 采购 / PMC |
| 促销 | 可售覆盖 **> 180 天**，且 120 天内无断货 | 促销去库存 | 运营 |

45 / 60 与系统默认海运一致：美西 45 天，美东 / 美南 / 美东南 60 天（`DEFAULT_SHIPPING_LEAD_BY_WAREHOUSE`）。90 ≈ 生产 50 + 美西海运 45；120 ≈ 生产 50 + 美东海运 60 + 入仓缓冲。180 即现有超储阈值 `DEFAULT_OVERSTOCK_THRESHOLD_DAYS`。

日均 ≈ 0、销售占比为 0、本仓又没有批次的空仓扫描，不进任何动作档。

### 用户角色

| 角色 | 看哪一档 | 典型操作 |
|------|----------|----------|
| 运营 | 调价、促销 | 调价、促销，不在本系统下单 |
| 发运 | 紧急发货、发货 | 对在产 / 本地可发批次安排出运 |
| 采购 / PMC | 下单 | 打开补货建议，采纳进 PMC |
| 管理员 | 全部 | 审计 |

### 用户故事

- 作为 **任一角色**，我在驾驶舱先看到各场景的 SKU 数，点一张卡片才进入该场景明细。
- 作为 **运营**，我点「调价」或「促销」，在明细里去做控销或清库存，不看到发运和下单队列。
- 作为 **发运**，我点「紧急发货」或「发货」，在明细里看本仓可发批次并跳到发运。
- 作为 **采购**，我点「90 天下单」或「120 天下单」，在明细里跳到补货建议。

### 非目标

- 不在本系统自动改价、自动建发运单或采购单。
- 不 PATCH 飞书占比与目的仓。
- 第一期不改落库类型全集，用读路径把现有行归到动作档。

## 2. 数据模型

沿用 `stock_alerts`、`inventory_health_snapshots`、开放供给批次、周转快照。不新增表。

API 派生：

| 字段 | 规则 |
|------|------|
| `daysToStockout` | 本仓时间轴 `stockoutDateConfirmed` 与今天的日历差；无断货日则为空 |
| `coverageDays` | 确定覆盖天数；无消耗且今日确定余额 > 0 视为无穷 |
| `action` | `price` / `ship_urgent` / `ship` / `order_tight` / `order` / `promo` / `none` |
| `noiseHint` | 日均 ≤ 0.1 且占比 ≤ 0 且本仓无开放批次时为 `zero_demand_empty_warehouse` |

`action = none` 的行只在「全部」里出现。

## 3. 页面

两层，和规划驾驶舱一致：概览在驾驶舱，明细在列表。

### 3.1 概览（规划驾驶舱「库存风险」）

放在现有「风险与履约」中，或单独一节替换其中的 7/15/30 天缺货、积压、来不及、低于补货点。卡片样式沿用 `PlanningDashboardPage`：白卡片、大数字、有风险时橙色描边，整卡可点。

| 卡片 | 主数字 | 副文案 | 点进去 |
|------|--------|--------|--------|
| 调价 | 该档 SKU 数 | 已断或发货/下单都赶不上 | `view=price` |
| 紧急发货 | 该档 SKU 数 | 45 天内断货 | `view=ship_urgent` |
| 发货 | 该档 SKU 数 | 46–60 天断货 | `view=ship` |
| 下单 · 90 天 | 该档 SKU 数 | 61–90 天断货 | `view=order_tight` |
| 下单 · 120 天 | 该档 SKU 数 | 91–120 天断货 | `view=order` |
| 促销 | 该档 SKU 数 | 可售覆盖 > 180 天 | `view=promo` |

主数字按 **SKU 去重**。副文案写清窗口，不把 6.6 万行当主数字。延期跟单、延期发运、数据问题、未定仓供应仍留在履约区，不并进这六张卡。

### 3.2 明细

路由 `/inventory/alerts?view=`。页头写场景名和窗口，例如「紧急发货 · 45 天内断货」。表保留本仓 / 全网合计两组。没有「五 Tab 切换」作为主路径；换场景回到驾驶舱再点另一张卡。审计用 `view=all`，不放在驾驶舱主区。

### 3.3 明细上的动作（按场景，也就是按角色）

| 场景 | 行上主动作 | 次动作 |
|------|------------|--------|
| 调价 | 打开该 SKU 规划（看断货日与可售） | 标记已处理 |
| 紧急发货 / 发货 | 打开该仓时间轴；若已有发运单则去发运列表 | 标记已处理 |
| 下单 · 90 / 120 | 打开补货建议（带 SKU） | 分仓时间轴、标记已处理 |
| 促销 | 打开该 SKU 规划 | 标记已处理 |

系统不自动改价、不自动建单。动作是跳到已有页面，由对应角色继续做。

## 4. 归档规则

输入是 **本仓确定断货日** 与 **确定覆盖天数**。同一行只取最紧急的一档。

```text
若 noiseHint 有值 → action = none

否则若 coverageDays > 180 且 (无断货日 或 daysToStockout > 120) → promo

否则若 daysToStockout == null → none

否则若 daysToStockout <= 0
     或 (daysToStockout < 发运周期 且 没有可发的本地/在产批次) → price

否则若 daysToStockout <= 45 → ship_urgent
否则若 daysToStockout <= 60 → ship
否则若 daysToStockout <= 90 → order_tight
否则若 daysToStockout <= 120 → order
否则 → none
```

发运周期：该仓 `resolveShippingLeadDays`，缺省美西 45、美东等 60、其他仓 60。

「可发批次」：开放批次池为 `local`，且生产状态不是 `in_production` / `qc_pending`（与时间轴预计档一致）。只有在产未完工时，45/60 天档仍显示发货，但标记「暂无可发，需等完工」，避免当成已经能上船。

### 和现有类型的关系

| 现有类型 | 归入 |
|----------|------|
| `overstock` 且覆盖 > 180 | 促销 |
| `stockout` 且断货日已过、又没有可发批次 | 调价 |
| `uncoverable_by_new_po` 且发运也赶不上 | 调价 |
| `stockout_horizon` 7/15/30 | 落在 45 天内 → 紧急发货 |
| `coverage_short` / `below_rop` / `below_safety` | 不单独成档；若断货日算出 61–120 天则进下单 |

没有本仓断货日、日均又大于 0 的覆盖不足，第一期放在「全部」，不塞进下单，避免把「供给为 0 但需求未进时间轴」误当成要下单。

### 数字怎么读

| 看到的 | 含义 |
|--------|------|
| 本仓未来需求 = 0，仍在调价/发货 | 断货日到了，但建议量为 0（日均很低或窗口内需求为 0） |
| 本仓有货，下单档需求很大 | 断货在 61–120 天；需求 = 建议量，或日均 × 总交期（预测 × 占比或历史） |
| 全网在库很大、本仓为 0 | 飞书合计，不是这个仓的可发库存 |

## 5. API

`GET /api/planning/dashboard` 增加六档 **SKU 去重计数**，供驾驶舱卡片。

`GET /api/alerts?view=price|ship_urgent|ship|order_tight|order|promo|all` 返回该场景明细，并带 `action`、`daysToStockout`。筛选在服务端完成。

---

## 6. 分期

**Phase 1：** `resolveAlertAction` + 单测；驾驶舱六张卡；点卡进入对应明细；行上按场景给跳转。

**Phase 2：** 发货明细展示可发批次数量；下单明细可按 SKU 折叠。

**Phase 3：** 扫描时写入 `action`，驾驶舱直接计数，不再事后归类。

## 7. 验收

| # | 场景 | 期望 |
|---|------|------|
| 1 | 断货日是今天或更早，且没有可发批次 | 调价 |
| 2 | 断货日在 30 天后，本地有已完工批次 | 紧急发货 |
| 3 | 断货日在 50 天后 | 发货 |
| 4 | 断货日在 80 天后 | 下单（90 天内） |
| 5 | 断货日在 100 天后 | 下单（120 天内） |
| 6 | 覆盖 > 180 且 120 天内无断货 | 促销 |
| 7 | DE 占比 0、日均 0、无批次 | 不进四档；全部里带噪声标记 |
| 8 | 本仓 0、全网 98 | 两列仍分开；动作按本仓断货日，不按全网合计 |
