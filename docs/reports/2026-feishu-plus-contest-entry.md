## 一、项目定位：为什么是「飞书+」而不是「又做了一个系统」

飞书+ 不是把 Excel 搬进多维表格，也不是单独上一个聊天机器人。本项目把飞书做成供应链操作系统的**协同层**：

| 飞书原生能力 | 在本项目中的角色 | 业务结果 |
|--------------|------------------|----------|
| 开放平台自建应用 | 统一身份与 API 凭证 | 飞书登录进业务系统，权限与岗位对齐 |
| 多维表格 | 业务人员日常台账入口 | 不改一线作业习惯，数据自动入湖 |
| 即时消息 | 预警 / 待办推送到群 | 人不再逐笔翻表、跨群催办 |
| 云文档 | 方案、SOP、参赛材料 | 全司可阅、评委可管 |
| aily（规划） | 计划确认等审批流 | 审批留在飞书，数量仍由引擎计算 |

**边界（评委常问）**

- **飞书做协同，不做账本**：权威口径在自建 PostgreSQL；飞书表是入口与回写面。  
- **AI 做解释与找人，不算数量**：补货量、覆盖天数、ROP/EOQ 由本地算法计算；LLM 只生成摘要、催办名单、预测解释，并受服务端收敛带约束，避免幻觉改数。  
- **不把业务锁死在低代码**：生产入口为自建 Docker Web + 飞书 SSO，便于复制到其他业务线。

## 二、背景与痛点：从「逐级流转」到必须「高效同步」

跨境电商供应链的决策窗口短、链路长：预测偏差、备货评审、工厂跟单、头程分账、库存口径，过去分散在迅捷 ERP、Excel、飞书表多套工具里。

### 改造前（逐级流转）

```
各岗位导出表 → 微信/飞书群催要对齐 → 人工筛选超期 → 周会过备货
        ↓ 口径经常不一致
补货决策落后 T+1 甚至更久；断货与积压事后才发现
```

### 七项核心痛点

1. **数据孤岛**：库存、主数据、跟单多套口径，对不齐就无法决策。  
2. **预测不准**：备货缺少可解释输入，计划与执行脱节。  
3. **备货评审慢**：依赖人工导出整理，次数高、口径乱。  
4. **跟单靠盯人**：大件待确认、超期靠人工筛表、重复沟通。  
5. **流程断档**：预测 → 计划 → 跟单 → 到货之间没有系统串联。  
6. **时效滞后**：手工上传导致补货决策晚一天，红灯发现晚。  
7. **管理者看不见**：没有漏斗与待办，只能开会催进度。

### 业务一句话诉求

- PMC：给我**可解释**的补货建议，而不是黑盒数字。  
- 采购：超期**自动找人**，不要我逐笔翻表。  
- 管理者：看板漏斗一眼看到卡在哪一环。

## 三、方案总览：飞书+ 五层栈

```
访问层  飞书登录 + 业务工作台（自建 Web）     Face
协同层  多维表格 / 群消息 / 云文档 / aily    Blood
智能层  Dify 工作流 · RAG · 研究 Agent      Neural
引擎层  scm-agent（算法 / 状态机 / Cron）    Brain
数据层  PostgreSQL · 日快照 · 任务审计       Memory
```

**效率飞轮（本项目的核心重构）**

> 数据自动到位（飞书表日更入湖）→ AI / 规则自动筛推 → 人在飞书或工作台确认例外 → 结果回写 → 次日再驱动。

人从「搬运数据、催办、对口径」退出，只保留确认、锁定与例外处理。

### 3.1 数据智能：五条飞书自动化链路（已生产）

每日上午集中完成入湖，业务上班即可用 T 日数据。

| 时刻 | 飞书源 | 系统产出 | 说明 |
|------|--------|----------|------|
| 07:00 | — | 缺货预警 + AI 摘要推群 | 规划引擎巡检 |
| 07:20 | 库存查询分仓明细 | 日快照归档 | 只读，不驱动补货 |
| 07:30 | 库存周转宽表（5800+ SKU） | 总览 + 补货输入 + 主数据联动 | 规划主数据源 |
| 08:00 | 大件备货申请表 | 全量覆盖本地 | 超期由工作流催办 |
| 08:05 | 采购跟单台账 | 与 PMC 跟单对齐 | 每日催办 |
| 08:00 | — | 跨境资讯研究 | 审核采用后写回飞书总表 |
| 周一 09:00 | — | 补货预测 | 数量本地算，文案可 AI 增强 |

随周转同步：**商品主数据自动创建 / 增量更新**，生命周期由销量计算，避免「先维护主数据才能算」的断档。

### 3.2 四大引擎（业务逻辑在引擎，不在 Prompt）

| 引擎 | 回答的问题 | 关键能力 |
|------|------------|----------|
| 数据智能 | 数据从哪来、是否可信、何时就绪 | 双跳同步、字段映射、日快照、任务互斥 |
| 库存规划 | 该不该补、补多少、何时下单 | 覆盖天数、健康灯、提前期、ROP/EOQ |
| 供应商 PMC | 计划如何下发、履约到哪步 | 计划确认、跟单状态机、到货回写 |
| AI 增强 | 谁该处理、怎么解释、SOP 怎查 | 催办、预警摘要、评分、预测解释、资讯研究 |

**规划触发（可向评委板书）**

> 覆盖天数 = 库存位置 / 预计日需求  
> 若覆盖 < 提前期 + 安全库存，或触及再订货点 → 生成可解释补货建议。

### 3.3 主闭环 8 节点（从试点功能串成业务流）

1. 飞书五类台账 Cron 入湖  
2. SKU 主数据对齐（无变化则跳过）  
3. 销售预测发布（含影响预览）  
4. 智能规划：补货建议、健康灯、预警  
5. PMC 计划确认，生成跟单  
6. 履约协同：状态推进 + AI 催办  
7. 到货登记，回写库存  
8. 经营看板复盘，回流下一轮预测  

跟单状态机：待确认 → 已确认 → 生产中 → 待发货 → 在途 → 部分到货 → 已收货（含异常 / 取消）。

## 四、AI 技术创新深度（评分维度 1 · 权重 30%）

对照细则：**业务流程重构 + 高技术门槛 + 防幻觉 + 稳定运行**。

### 4.1 不是「通用 AI 包装」，而是 AI 与业务逻辑深度整合

| 场景 | AI 做什么 | 系统硬约束（防幻觉） |
|------|-----------|----------------------|
| 缺货预警 | 生成飞书群可读摘要 | 预警行由本地规则算出，AI 不得增删 SKU、改数量 |
| 补货建议 | 增强原因文案 / 风险提示 | `suggestedQty` 仅本地 EOQ/ROP，Workflow 禁止覆盖 |
| 单 SKU AI 辅助预测 | Dify 输出日均与理由 | 服务端把结果收敛到系统水位 ±10%（有外生因素 ±12%），失败则回退系统值 |
| 大件 / 跟单催办 | 按超期规则筛人、分组推送 | 超期天数、状态来自飞书表字段，不是模型「感觉超了」 |
| 客服回复质量 | 四维打分 + 评语 | 及格线可配，结果可复核 |
| 跨境资讯 | 检索、抽取、分类 | 必须人工审核采用后才写入飞书总表 |
| 知识问答 | FAQ / 可选 RAG | 未配置 Dify 时自动降级本地助手，不空转 |

### 4.2 多场景复杂任务，用流程控制而不是「再写一句 Prompt」

- **分层预测**：组别 → 品类 → 平台 → SKU，加总一致与锁定保护，避免「每个 SKU 各说各话」。  
- **库存规划**：头寸、可售 ETA、断货修正、交期档案，建议带结构化解释。  
- **任务治理**：Compose Cron + `X-Cron-Secret` + 任务互斥 + `task_runs` 审计，规模化后可连续跑、可追溯。  
- **降级策略**：Dify 未配置或故障时，本地算法与 FAQ 仍可用，业务不因模型中断而停摆。

### 4.3 运行稳定性

- 生产形态：Win11 专用机 + Docker Compose + Cloudflare Tunnel。  
- 日调度：预警、五条入湖、资讯、催办、周更补货，已在真实业务数据上连续运行（自 2026-07 生产基线起，**已满 1 个月、冲刺 3 个月**）。  
- 版本基线：v1.0.3（2026-08）；库存规划 P0–P3、飞书同步、Cron sidecar 均已发版。

**自评锚点**：技术深度与防幻觉达到「优秀」档特征；稳定运行时长按赛制「≥3 个月」仍在爬坡，演示时如实说明时间线，用任务日志证明「每天在跑」而不是试点周报。

## 五、业务提效与价值创造（评分维度 2 · 权重 30%）

对照细则：**管理自动化 + 年化经济效益**。平分时本维度权重大于创新性，必须讲清「钱从哪来、是否可验收」。

### 5.1 管理逻辑变成系统自动执行

| 过去靠人 | 现在靠系统 |
|----------|------------|
| 每天对三套表口径 | 飞书入湖 + 主数据联动，T 日就绪 |
| 逐笔翻表找超期 | 待办 / 异常清单 + 定时催办 |
| 周会才发现断货 | 07:00 红黄灯巡检推群 |
| 管理者催办、对进度 | 看板漏斗 + 今日待办 |
| 头程费用手工拆柜 | 按工厂 / 柜号系统分摊 |

管理者从「事务性盯人」转为「看漏斗、批例外」。

### 5.2 年化经济效益（脱敏口径 · 可答辩）

**记账原则**：不把「整平台释放 X 亿」打成已兑现奖金；**工时类已能量化的先入账**，资金占用类按情景单列，供评委按证据权重打分。

#### A. 已能量化的效率红利（工时 → 金额）

全成本按 **150 元 / 工时** 折算（岗位年全成本约 27 万 ÷ 约 1800 有效工时，可按公司人效口径替换）。

| 能力点 | 测算 | 年化工时 | 年化金额 |
|--------|------|----------|----------|
| 销量预测 / 备货评审 | 约 31,740 次 × 10 分钟 | ≈ 5,290 小时 | ≈ **79.4 万元** |
| 采购跟单 / 大件催办 | 10 人+团队，人均每日约 20 分钟 | ≈ 1,000+ 小时 | ≈ **15.0 万元** |
| FOB 头程分账 | 系统分摊替代手工拆对账 | ≈ 480+ 小时 | ≈ **7.2 万元** |
| **合计（效率项）** | | **≈ 6,770 小时** | **≈ 101.6 万元** |

效率项单独已跨过细则「优秀」档 **年化 ≥ 100 万元** 门槛。数据自动化（日手工导入 → 0）作为使能层，**不重复折进总账**。

#### B. 经营质量情景（待业务按削减比例验收，不计入上方合计）

2025 年参考基线：大件审批备货与预报采购成本之间存在约 **4 亿元**量级「多备货」差额。预测准确率提升后的释放资金 = 4 亿 × 冗余库存削减比例。

| 情景 | 削减比例 | 预计释放资金 | 转投毛利示意（50% 转投 × 25% 毛利率） |
|------|----------|--------------|----------------------------------------|
| 保守 | 5% | 约 0.20 亿 | 约 250 万 |
| 基准 | 10% | 约 0.40 亿 | 约 500 万 |
| 进取 | 20% | 约 0.80 亿 | 约 1,000 万 |

另有缺货挽回（受影响 SKU 销售额 × 缺货率降幅），上线后按准确率与缺货率环比验收。

**演示口径建议**：主打「效率项 ≥ 100 万已可算」；库存资金作为**上行空间**，避免被追问「4 亿是否已进账」。

## 六、方案可推广性与影响力（评分维度 3 · 权重 20%）

对照细则：**积木化、目标用户覆盖、内外认可**。

### 6.1 积木，而不是绑死在跨境家居

可直接拆走、换表就能复用的模块：

| 积木 | 换业务线时改什么 | 不改什么 |
|------|------------------|----------|
| 飞书 OAuth + RBAC | 应用可见范围、角色菜单 | 登录与权限模型 |
| 多维表格同步器 | 列名映射、table_id | 拉取 / 回写 / 快照 / 互斥 |
| Cron 任务框架 | 时刻与业务 API | sidecar、密钥、审计 |
| 规划引擎 | 提前期、安全库存参数 | 覆盖天数公式与建议结构 |
| AI 工作流 | 催办规则、群 webhook | 「系统算数、AI 叙事」边界 |
| 资讯研究 | 词表与来源 | 审核门禁再入飞书 |

**复制路径（可执行）**：新部门提供 1 张飞书多维表格 + 1 个岗位角色 → 配环境变量 → 日调度接入 → 先跑通「入湖 + 待办」，再挂规划与 AI。

适用：计划、采购、物流费用、客服质检、情报值班等「表在飞书、人在群里」的条线；不限跨境电商。

### 6.2 覆盖与成熟度（如实）

- **已从「做功能」进入日常业务流**：库存周转、查询快照、大件备货、采购跟单、预测与补货、FOB、资讯回写飞书，均在生产调度中。  
- **目标用户**：供应链计划 / 采购 / 物流费用相关岗位；SKU 级周转表全量拉取（5800+）。  
- **尚未宣称**：全公司全员覆盖、行业级外部奖项。  
- **下一步可讲的推广**：飞书工作台统一入口、aily 计划审批、知识库 RAG、预测准确率驾驶舱下沉到销售运营。

**自评锚点**：逻辑通用与局部落地达到「良好」偏「优秀」；外部奖项暂无，不虚构。用「可复制架构 + 已全量拉表」换影响力分，比空报奖项更稳。

**三句防幻觉铁律（必背）**

1. 数量只由本地引擎算。
