以飞书为协同底座、妙搭为统一入口、Dify 为 AI 神经、scm-agent 为业务计算引擎。在集团数字化蓝图中，率先回答并闭环：**该不该补、补多少、何时下单、能否按期到货**。

## 一、背景 · 现状 · 要解决的问题

### 核心痛点（7 项）

**数据孤岛**  
迅捷 ERP、Excel、飞书表多套并存，库存与主数据口径经常不一致。

**预测不准**  
销量预测偏差大，备货决策缺乏可靠输入，计划与执行经常脱节。

**备货效率低**  
评审依赖人工导出整理，效率低、口径不统一，准确性难以保障。

**调拨组柜薄弱**  
调拨/组柜销量占比低，规则与标准不一，跨仓协同与组柜决策困难。

**采购跟单繁琐**  
逐笔查表、重复沟通、进度汇总耗时长，大件待确认与超期靠人工筛选。

**流程断档**  
预测、计划、跟单、到货之间缺少系统串联，进度靠人工盯人。

**时效滞后**  
手工导出上传，补货决策常落后 T+1 甚至更久，断货积压事后才发现。

### 业务诉求

PMC 要可解释建议；采购要超期自动找人；管理者要看板漏斗。

### IT / 飞书诉求

统一入口、统一身份、敏感数据可控、对齐妙搭/AI+。

### 不做清单

正式 PO/付款、MES、船司 API、供应商门户、SAP 实对接。

## 二、价值模型 · 平台基建 + 能力点量化

### 价值记账原则

系统侧只谈「使能与基建」：统一数据、统一引擎、统一入口、可审计。金额与工时类收益挂到具体能力点上验收，避免「整平台承诺释放 X 亿」；4 亿等多备货数字仅作「销量预测及备货」点的历史参考基线。

### 2.1 平台基建价值（定性 · 不背总账）

- **定位**：scm-agent 是平台基建——数据入湖、引擎计算、权限审计、飞书/妙搭/Dify 集成。
- **价值归属**：可量化收益归属各业务能力点，不把整系统当作「一笔总账」承诺收益。
- **战略对齐**：落实集团「数智驱动高效」——效率工程 + 数据与知识双驱动。
- **主轴突破**：在计划 · 采购 · 物流 · 运营四列验证「数字化 → 自动化 → 智能化」递进。
- **效率范式**：数据自动到位 · AI 推送待办 · 人只做确认与例外处理。
- **安全可控**：自建 Docker · 飞书 SSO · 敏感字段分级 · 推送脱敏。

**效率飞轮**：数据自动到位 → AI 自动筛推 → 人在飞书确认 → 闭环回写 → 次日再驱动各能力点业务。

基建三要素：数据基建（五条链路日更入湖）· 引擎基建（规划/PMC/AI 可复用）· 协同基建（飞书登录/RBAC/妙搭入口）。

**能力点 A · 销量预测及自动备货**（运营 · 计划）  
价值类型：资金占用、转投毛利、缺货挽回、备货评审工时。量化状态：已量化。角色：主价值点 A。

**PMC 履约闭环**（计划 · 采购）

**能力点 B · 采购跟单 / 大件催办**（采购）  
价值类型：降本、提效工时、作业模式升级。量化状态：提效已量化。角色：采购主价值点。

### 2.3 能力点 A · 销量预测及自动备货

**口径说明**  
2025 年整年参考：大件审批备货金额约 12 亿，SKU 预报−财务采购成本约 8 亿，差额约 4 亿视为「多备货」历史基线。实际释放资金 = 4 亿 × 冗余库存削减比例，须上线后按削减比例验证；新增毛利不能直接等同于释放资金。

**四维价值模型**

1. **减少库存资金占用**  
   提升预测准确率，削减冗余备货。测算：预计释放资金 = 4 亿元 × 冗余库存削减比例。

2. **创造盈利机会**  
   释放资金转投高需求/高周转/高毛利商品。测算：预计新增毛利 = 可释放资金 × 可转投比例 × 相关商品毛利率。

3. **减少缺货损失**  
   提高 SKU 级预测准确率，降低断货概率。测算：预计挽回毛利 = 受影响 SKU 销售额 × 缺货率降幅。

4. **提升备货决策效率**  
   自动趋势分析、预测结果与评审明细。测算：31,740 次 × 10 分钟 ≈ 0.53 万工时/年。

**多备货基线情景（2025）**

- 保守（削减 5%）：预计释放约 0.20 亿；转投毛利示意约 250 万量级（按 50% 转投、25% 毛利率）。
- 基准（削减 10%）：预计释放约 0.40 亿；转投毛利示意约 500 万量级。
- 进取（削减 20%）：预计释放约 0.80 亿；转投毛利示意约 1,000 万量级。

### 2.4 能力点 B · 采购跟单 / 大件催办

**降本**  
减少人工查表、重复沟通与进度汇总；提前发现延期风险，降低加急生产、临时调拨、改船期及缺货等成本（待业务继续采数）。

**提效**  
按系统待办/异常清单处理，替代逐笔翻表跟进。每人每日节省约 20 分钟；10 人+团队年预计节省 **1000+ 工时**。

**作业模式升级**  
从「逐笔跟进全部订单」转为「待办 + 异常清单」；订单状态统一展示，减少跨部门重复确认与交接成本。

### 2.5 能力点 C · FOB 分账

头程费用按工厂/柜号系统分摊，减少手工拆分与对账。年预计节省 **480+ 工时**；所属数字化节点：物流 · 费用计划与账单核对。

### 2.6 其他能力点 · 量化方向（待采基线）

- 库存健康/预警：预警响应时效、红灯 SKU 环比。
- PMC 履约闭环：准时到货率、异常关闭周期。
- 数据自动化：日手工导入次数 → 0（基建使能，不折算平台总收益）。

## 四、四大核心引擎

**数据智能引擎**  
回答问题：数据从哪来、是否可信、何时就绪。能力：双跳同步、字段映射、日快照、主数据联动、任务互斥。产出：Eliminate 手工导入；T 日数据就绪。

**库存规划引擎**  
回答问题：该不该补、补多少、何时下单、会否断货/积压。能力：库存位置、覆盖天数、健康灯、提前期、metrics。产出：红黄灯可行动；建议可采纳。

**供应商 PMC 引擎**  
回答问题：计划如何下发、履约到哪步、何时可售。能力：PMC 计划、跟单状态机、交期提醒、到货回写。产出：履约可追踪；到货闭环库存。

**AI 增强引擎**  
回答问题：谁该处理、怎么解释、SOP 怎查。能力：Dify 催办、预警摘要、评分、预测、RAG。产出：AI 找人；人确认；数量本地算。

**规划触发公式**：覆盖天数 = 库存位置 / 预计日需求；若覆盖 < 提前期+安全库存，或触及 ROP → 建议。

**AI 边界**：数量本地算；预测/资讯建议态；推送脱敏。

## 六、业务闭环体系

### 主闭环 8 节点

1. **N1 数据入湖**：Cron 拉取飞书五类台账 → 数据智能引擎 → 快照发布  
2. **N2 主数据对齐**：SKU 创建/更新、生命周期 → 无变化跳过  
3. **N3 需求发布**：预测版本 + 影响预览 → 人工确认  
4. **N4 智能规划**：补货建议、健康灯、预警 → 可解释  
5. **N5 计划确认**：PMC 草稿 → 确认 → 生成跟单  
6. **N6 履约协同**：状态推进、交期、异常 → Dify 推送  
7. **N7 到货闭环**：登记收货、回写库存 → 计划完成  
8. **N8 经营复盘**：看板漏斗、驾驶舱 → 回流预测  

### 跟单状态机

待确认 → 已确认 → 生产中 → 待发货 → 在途 → 部分到货 → 已收货；另有异常/取消分支。

### 子闭环

- **库存健康闭环**：快照 → 健康计算 → 补货灯回写 → 总览 → 预警推群（07:00 主动发现）
- **采购催办闭环**：飞书 → 同步 → Dify 筛超期 → 企微 → 人处理
- **预测准确率闭环**：基线 → 发布 → 补货采用 → 回测 → 纠偏
- **资讯情报闭环**：采集 → 审核 → 采用入飞书

## 十、安全与治理

- **身份认证**：飞书 OAuth + 邮箱；可强制登录
- **权限控制**：菜单级 RBAC；按岗位配置可见模块
- **数据主权**：PostgreSQL 自建 Docker，不上公有云 SaaS
- **网络边界**：Cloudflare Tunnel + HTTPS
- **任务安全**：Cron 需 X-Cron-Secret
- **密钥管理**：密钥存 .env，不进仓库
- **敏感隔离**：成本/供货方权限可见；推送脱敏
- **AI 边界**：数量本地算；建议态人工确认
- **审计追溯**：操作日志 + task_runs
